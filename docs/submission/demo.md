# Live demonstration runbook

Status: rehearsal and live integrated evidence pending. Never present fixture output as a live run.

## Before the session

Record the final SHA, consented device inventory, HTTPS/campus SSID reachability, Docker/verified CUDA, cached immutable models/images and approved external LLM access. Prepare a non-sensitive EN/ZH corpus, image dataset with fixed train/validation split and own-code project. Confirm browser assets work without CDN and that fresh planning failure does not stop existing prepared jobs. Collect matched standalone baselines with at least three repeats. No invented speedup claims.

## Present the service

1. Open console inventory and explain compute/control/validation roles. Connect a laptop with explicit consent and show actual preflight and budgets.
2. Ask the audience for a new corpus of the supported document type. In the portal choose files, show excluded secrets and selected external-LLM text, prepare the plan, and answer any question.
3. Review the execution preview and Run. Show at least two physical devices doing useful work in the same map job. The single GPU alone is not evidence of pooling.
4. Search the published index and show excerpts and sources. Show accepted units and actual correctness-validation depth.
5. With the owner's consent, stop a CPU worker during another map run. Show retry of unfinished work, rejection of stale results, and one accepted result/credit per unit. Do not confuse this fault series with normal throughput.
6. Open matched standalone / single-service / pool measurements, raw exports, efficiency, speedup, utilization windows/gaps and a measured bottleneck. Let the judge change concurrency or inputs and create a new experiment.
7. Upload/run own train.py or the image recipe; show model weights and metrics. Interrupt GPU training and demonstrate recovery from the last complete compatible published checkpoint after the GPU returns. Plain scripts without resume support restart explicitly.

## If something fails

Show the actual state and next action: waiting_for_capacity for missing GPU, preflight failure for missing runtime, reconnecting for network loss, or a retained upload and planner error for LLM outage. Do not substitute prerecorded success or silently run GPU work on CPU. If campus client isolation blocks routing, use only an approved reachable campus deployment.

## Evidence to save

Final SHA; experiment configuration/manifests; standalone and pool raw records; reference validation provenance; task/attempt timestamps and digests; accepted-unit counters; retry/cancel/late-result receipts; complete checkpoint publication and resume evidence; outputs; utilization samples; cost assumptions; user feedback if actually collected.

Acceptance remains pending until these checks are performed on real integrated devices.
